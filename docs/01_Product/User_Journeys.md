# AutoQA AI — User Journeys

**Version:** 0.1 Draft

## Journey 1 — Requirement to verified automation

Connect project → submit requirement → inspect extracted criteria/risks → review strategy → approve scope → monitor generation → inspect verification → review diff/evidence → publish for review when permitted.

## Journey 2 — Failure investigation

Open failed run → review classification and confidence → correlate test step, trace, logs and network → compare previous runs/source changes → confirm product defect, automation defect, environment issue, flake or unknown → create follow-up action.

## Journey 3 — Existing framework onboarding

Connect repository → analyze conventions and current coverage → review compatibility/gaps → approve extension rules → generate a small reference test → validate in CI → establish project memory.

## Journey 4 — Governance

Configure roles, environments, action approvals, budgets, retention and allowlists → observe audit and policy violations → revise policy with recorded decision.

## Journey quality

Each journey must define entry conditions, actor, happy path, alternative paths, permission failures, cancellation, recovery, artifacts, telemetry and exit criteria.
