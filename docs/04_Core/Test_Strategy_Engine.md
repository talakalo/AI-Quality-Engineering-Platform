# AutoQA AI — Test Strategy Engine

**Version:** 0.1 Draft

## Purpose

Choose the smallest reliable combination of unit, component, contract, API, integration, browser, accessibility and non-functional checks that addresses approved risks.

## Inputs

Approved requirement, risk register, system analysis, existing coverage, framework capabilities, environment/data constraints and project policy.

## Outputs

Objectives, test layers, prioritized scenarios, exclusions, data/fixtures, environment, mocks, observability needs, execution groups, verification method, traceability and estimated cost.

## Rules

Prefer lower deterministic layers; justify browser tests; avoid duplicate coverage; include negative and permission cases; expose untestable requirements; require human approval before generation.

## Metrics

Expert plan score, redundancy, risk coverage, reviewer edits, downstream acceptance, run cost and defect yield.
