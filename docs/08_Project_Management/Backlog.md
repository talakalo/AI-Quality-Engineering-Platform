# AutoQA AI — Backlog

**Version:** 0.1 Draft | **Status:** Planning only; not implementation authorization

## Prioritization

Order by user value, risk reduction, dependency, learning value, and cost. Every story needs acceptance criteria, boundary reference, security impact, telemetry, tests, and Definition of Done.

## Epic E0 — Product foundation

Approved specifications, ADRs, repository structure, CI quality gates, environments, design system foundation, observability baseline, and reference repositories.

## Epic E1 — Identity, tenancy and projects

Organizations, membership, roles, projects, repository connection, environment configuration, policy and audit.

## Epic E2 — Context and website analysis

Repository indexing, framework/convention detection, requirement ingestion, website analyzer, evidence-backed application map, and context freshness.

## Epic E3 — Planning and approvals

Risk model, test-plan generation, human editing, versioning, approval workflow, policy evaluation, and plan traceability.

## Epic E4 — Automation generation

Playwright detector, extend/bootstrap modes, fixtures, data builders, API/browser tests, patch creation, diff review, and documentation.

## Epic E5 — Isolated execution

Workspace lifecycle, worker isolation, commands, dependency install, browsers, environment access, cancellation, artifacts, quotas, and cleanup.

## Epic E6 — Verification and failure intelligence

Static/structural/traceability gates, negative proof, repeatability, evidence model, failure classification, confidence and waiver workflow.

## Epic E7 — Dashboard and evidence

Project overview, approval inbox, live runs, results, artifacts, findings, traceability, cost, policies, and audit export.

## Epic E8 — GitHub and CI delivery

GitHub App, commit pinning, checks, draft PR publication with approval, GitHub Actions templates, webhooks, idempotency and contract tests.

## Epic E9 — Production hardening

Threat model closure, SLOs, scale/performance, DR, retention/deletion, incident response, accessibility, evaluation thresholds, cost controls, and release readiness.

## Task template

Problem; user outcome; scope/out-of-scope; dependencies; acceptance criteria; technical notes; security/privacy; observability; test/evaluation plan; rollout/rollback; Definition of Done.
