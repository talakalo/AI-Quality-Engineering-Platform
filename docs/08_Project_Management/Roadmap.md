# AutoQA AI — Roadmap

**Version:** 0.1 Draft | **Status:** Outcome-based, dates not committed

## Phase 0 — Specification and risk retirement

Approve documents, resolve boundary decisions, threat-model execution, validate workflow/sandbox/model spikes, define reference repository and measurable baselines.

**Exit:** approved implementation scope, architecture decisions, critical risks retired, backlog ready.

## Phase 1 — Engineering foundation

Identity/project skeleton, database/migrations, API contracts, CI, observability, audit, basic UI, durable operation model and isolated worker proof.

**Exit:** secure end-to-end skeleton executes a deterministic sample job with audit and evidence.

## Phase 2 — Plan-to-test vertical slice

Repository analyzer, requirement intake, test strategist, approvals, Playwright generator, targeted execution and diff/evidence review.

**Exit:** reference feature produces a reviewable, passing automation change under human approval.

## Phase 3 — Trust and verification

Negative proof, repeatability, traceability, classification, confidence, policy enforcement, prompt-injection tests and evaluation harness.

**Exit:** system detects controlled defects, classifies reference failures, and meets defined false-confidence thresholds.

## Phase 4 — Operational MVP

Dashboard completion, GitHub/CI integration, quotas/cost, retention, accessibility, SLOs, support/runbooks and onboarding.

**Exit:** design partners complete core workflow with acceptable success, security, reliability and cost metrics.

## Phase 5 — Limited availability

Controlled customer onboarding, production monitoring, incident and feedback loops, scale validation, evaluation expansion and backlog correction.

**Exit:** release gates sustained over an agreed observation window.

## Future candidates

Additional frameworks/languages, multi-repository changes, mobile, performance and visual testing, enterprise SSO/SCIM, on-premises execution, and higher autonomy—only through Product Boundary changes.
